# Развёртывание контент-завода Tzoar Lab

Архитектура и обоснование решений — в `../docs/video_factory_v2.md`.
Политика, исполняемая кодом, — в `../policy/POLICY.yaml`.

## Что здесь есть

```
docker-compose.control.yml   control plane: Postgres, Redis, MinIO, Qdrant,
                             оркестратор, воркер. GPU не требуется — ставится
                             на обычный Contabo VPS (€15–40/мес)
docker-compose.gpu.yml       GPU-нода: MuseTalk, Chatterbox TTS, WhisperX,
                             InfiniteTalk. Ставится отдельно, на любой хост с
                             NVIDIA — Contabo cloud GPU, RunPod, Vast
orchestrator/                состояние, политика, валидаторы, стадийная машина
smoke_test.py                проверка, что запреты политики реально исполняются
```

Разделение неслучайно: нагрузка объёмного контура — порядка 20 минут GPU в
сутки, поэтому выделенная L40S за €600/мес на старте не нужна, а control plane
должен работать круглосуточно и стоить дёшево.

## Быстрый старт (control plane)

```bash
cd deploy
make env                 # создаст .env из шаблона
$EDITOR .env             # заполнить пароли
make up                  # поднять стек
curl -s localhost:8080/status | jq
```

Проверка, что политика работает:

```bash
docker compose -f docker-compose.control.yml run --rm orchestrator python smoke_test.py
```

## GPU-нода

Разворачивается на отдельном хосте с NVIDIA-драйвером и
`nvidia-container-toolkit`:

```bash
export S3_ENDPOINT=http://<control-plane-ip>:9000
make gpu-up
```

Затем в `.env` control plane указать `GPU_NODE_URL=http://<gpu-ip>:9200` и
`GPU_PRICE_PER_HOUR=<ставка>`. Ставка пишется в журнал стоимости, из которого
через несколько десятков роликов получается собственная таблица цен.

Пока `GPU_NODE_URL` пуст, работает `NullBackend`: конвейер доходит до стадии
рендера и честно останавливается с блокером. Это сделано намеренно — тихая
имитация рендера хуже явной остановки.

## Модель работы

Ключевой инвариант:

> Объёмный контур не создаёт утверждений. Он переупаковывает только те, что
> прошли гейт в атласе. Сценарий, ссылающийся на утверждение без статуса
> `verified`, не проходит валидацию и не может быть опубликован.

Человек утверждает **инвентарь** (записи атласа, ~9 в неделю), а не каждое из
300 видео в месяц. Одна проверенная запись даёт ~8 роликов: 4 ракурса × 2 языка.

```bash
# 1. завести запись атласа
curl -XPOST localhost:8080/atlas -H 'content-type: application/json' -d '{
  "slug":"chazaka-presumption","cluster_id":412,
  "title_ru":"Презумпция и владение","title_en":"Presumption and possession",
  "experiment_lock":"sha256:..."}'

# 2. гейт inventory — без experiment_lock утверждение отклоняется
curl -XPOST localhost:8080/atlas/1/approve -H 'content-type: application/json' \
     -d '{"approved_by":"vadim","note":"источники сверены"}'

# 3. дальше воркер сам создаёт ролики, соблюдая кулдаун и лимит на канал
curl -s localhost:8080/status
```

Отзыв утверждения находит все производные ролики:

```bash
curl -XPOST localhost:8080/claims/7/retract -H 'content-type: application/json' \
     -d '{"reason":"источник прочитан неверно"}'
```

## Что проверено, а что нет

Проверено запуском:

- валидаторы политики — 24/24 в `smoke_test.py`, включая блокировку выдуманной
  цитаты, неутверждённого утверждения, галахического постановления, шаблонного
  сценария, синтетической персоны, нераскрытого синтеза;
- стадийная машина, кулдаун инвентаря, распространение ретракции;
- импорт API (14 маршрутов) и воркера;
- синтаксис обоих compose-файлов.

Не проверено запуском (нет GPU и демона Docker в среде сборки):

- поднятие контейнеров control plane;
- образы GPU-ноды — `gpu/*/Dockerfile` нужно дописать под конкретные версии
  CUDA целевого хоста, они зависят от того, какой GPU будет выбран;
- интеграции публикации (YouTube OAuth, Telegram, LinkedIn) — заготовлены
  переменные окружения, кода ещё нет.

## Порядок дальнейших работ

1. Поднять control plane на Contabo VPS, прогнать `smoke_test.py`.
2. Загрузить снимок корпуса в Qdrant, зафиксировать `CORPUS_SNAPSHOT`.
3. Снять B-roll автора и референс голоса (RU и EN).
4. Поднять GPU-ноду посуточно, замерить реальное время рендера, наполнить журнал.
5. Пилот: 1–2 ролика в день, 100% ручной контроль, две недели.
6. Рост до 5 в день по метрике удержания, переход на выборочный контроль 15%.
